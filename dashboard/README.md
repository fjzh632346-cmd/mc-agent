# 项目进度看板

两个页面，右上角切换：

- **进度** —— 进度到哪、什么挡着路、AI 干了多少活
- **能力** —— 林夏现在到底会做哪些事，谁优先，谁跟谁冲突

## 怎么打开

双击 `dashboard\启动进度看板.bat`，浏览器会自动开。看完直接关掉那个黑窗口就停了。

也可以手动：

```powershell
cd D:\code\MC-blueprint-ir-v1
node dashboard\server.js
```

然后浏览器打开 http://localhost:4321

**不需要 npm install** —— 这个看板只用 Node 自带的功能写的，没有任何外部依赖。

## 上面的东西从哪来

**自动抓的，不用管：**

| 看到的 | 来源 |
|---|---|
| AI 干活的量、最近改动、有多少没存档 | git 提交记录 |
| 最近验收结果 | `acceptance/reports/latest-summary.md` |
| 工程健康检查（大文件、残留垃圾、日志堆积） | 直接扫文件大小 |
| 待决事项 | `docs/decision-needed.md` |

**能力页的东西也全是自动读的：**

| 看到的 | 从哪读的 |
|---|---|
| 会做哪些事、哪些会真动身体 | `ai/action-keys.js` |
| 一句话怎么走到动作 | `ai/intent-to-task.js` |
| 优先级档位（保命级/优先/常规/闲时） | `systems/task-arbitration/task-priority-manager.js` |
| 每条能力要抢哪几样资源 | `tasks/*-task.js` 里的 `requiredLocks` |

代码里加一条新能力，能力页自动就有，不用来这儿登记。
只有中文名和白话说明是人写的，在 `dashboard/capabilities.js` 顶部的 `LABELS` 里 ——
没写的照样会显示，只是显示英文 key。

**要人定的，在网页上点：**

任务清单 —— 状态、优先级、名称、备注，点任意一条就能改，改完自动保存。
你不需要打开任何文件。

## 能力页怎么看

三种分组方式，回答三个不同的问题：

- **按用途分** —— 它到底会干哪些活
- **按优先级分** —— 同时来了一堆事，谁先谁后
- **按抢占的资源分** —— 谁跟谁没法同时做

点任意一条能力，右边会显示它的完整链路（你说一句话 → 听懂成什么 → 走哪个任务 → 占用哪些资源）、
共用同一套代码的其他能力、以及跟它抢资源的能力。

**「优先级」有两个数，别混：**

- 彩色标签（保命级／优先／常规／闲时）是**仲裁档位** —— 决定能不能打断正在做的事
- 右边灰色小数字是**入队序号** —— 同一档位里谁先被拿出来做，数字大的先

**「六种资源」是什么：** 走动、打斗、背包、挖掘、放置、合成。同一时间一种资源只能给一个任务用，
这是防止两个任务同时指挥身体把事情搞乱的机制。抢同一样资源的能力，天然没法同时做。

单条能力的链接可以直接分享，形如 `http://localhost:4321/#caps=BUILD`。

## 数据存在哪

- `board-data.json` —— 你在网页上改的任务清单，**这个是你的数据，别删**
- `board-seed.json` —— 首次启动时的初始清单，之后不再读取

看板**只读**项目文件，不会修改你的代码、日志或验收报告。

## 端口被占用了

```powershell
set DASHBOARD_PORT=4322

```

## 图上的「工作时长」准吗

是估算。算法：把提交时间挨得近的（间隔 90 分钟以内）算作一段连续工作，
段长 = 最后一次提交 - 第一次提交 + 25 分钟（第一次提交之前总得先干一会儿）。

所以它反映的是**投入的节奏和相对多少**，不是打卡记录。
一次提交都没有的日子不会出现在图上。
