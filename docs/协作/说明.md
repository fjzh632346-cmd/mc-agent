# 协作协议 · 建造线（固定，不要改动本文件的结构）

**你在 `D:\code\MC-blueprint-ir-v1`。这是建造线。**

本项目有三方参与：

| 角色 | 是谁 | 干什么 |
|---|---|---|
| **老板** | 项目所有者 | 拍板决策。不看代码，只看白话结论 |
| **开发** | Cowork 里的 Claude | 出任务、审报告、翻译成白话给老板 |
| **施工** | 你（Claude Code） | 在本机读写代码、跑测试、跑真机验收 |

老板**不再手工搬运任何内容**。三方全部通过 `docs\协作\建造\` 下的两个文件交换信息。

## 你每次会话必须做的事

### 1. 开场

```powershell
cd D:\code\MC-blueprint-ir-v1
```

按顺序读（**全部在本 worktree 内，不要去别的目录**）：

```text
AGENTS.md                  项目铁律，永远最高优先级
docs\协作\建造\给CC.md      本轮要你干什么
docs\协作\建造\CC反馈.md    上一轮你自己写的结果，看有没有未了结的
```

然后跑：

```powershell
git status --short
git log --oneline -10
git branch --show-current
npm test
```

### 2. 干活

严格按 `给CC.md` 的范围。它没写的不要做。

### 3. 收尾（这一步不能省）

把结果写进 `docs\协作\建造\CC反馈.md`，格式见下面第 3 节。

> **不要发链接。不要只在聊天里回复。不要新建别的报告文件。**
> 老板看不到你的聊天窗口，开发只读这一个文件。
> 写进文件了才算交付；没写就等于没做。

写之前：如果反馈文件里还有上一轮的内容，先整份挪到
`docs\协作\历史\第N轮-简短标题.md`，再重写。**历史目录只增不删。**

## 真机验收：专用服务器已建成，不再需要老板开游戏

第 3 轮已搭好本地专用服务器（`D:\code\MC-server\`）。

```powershell
# 启停
scripts\mc-server.ps1 start | stop | status

# 起 bot 必须带这两个环境变量
$env:MC_WORLD_ID = 'building-A:新的世界'   # 不带则 48 条施工记录全部认不出、无法续建
$env:MC_PORT = '25565'
```

- 起进程用 `Start-Process`，**不要用 `Start-Job`**（子进程会随工具会话被杀，已踩过）
- **长活进程（服务器 / bot / 保姆脚本）用 `scripts\start-detached.ps1` 起**（作业外，活到 Claude Code 宿主退出为止，够一轮用；第 17 轮证伪它**不能**跨会话存活——老板决策 #54 放弃再验）。作业外进程不随会话自动清理：**每轮真机收工你自己 `Stop-Process` bot（过滤时排除 `$PID`）+ RCON 优雅停服**。要在你收工后还留着的服务器由老板自己开窗口起，与你无关
- 停服务器必须走 RCON 优雅停，**不要杀进程**（会损坏世界）
- **停工即收**：保姆脚本判停手（同砖三败、预算到点）后**立刻收 bot 或先 tp 回工地**，不要让她闲置——工地锚点宽限 3 分钟到期她会往老基地跑（离工地 589 格），第 18 轮跑到半路两连败脱困。这是设计内行为（开发定不改宽限），靠操作规避。等待循环每次打印保姆脚本尾行，不要按事件计数增量判断（第 20 轮漏看停手 13 分钟）
- **收工只杀本线进程**（老板 2026-09-05，第 20 轮误杀修缮线 bot 后加）：`Stop-Process` 前**必须按工作目录或所连端口核对**（`Get-CimInstance Win32_Process` 看 `CommandLine` 里的路径是本 worktree；或 `Get-NetTCPConnection` 看它连的是本线端口），**只关本线的**。「命令行里含 bot」这种过滤不许用——另一条线的 bot 可能同时在线
- ONLINE-GATE 四信号见 `docs/CODEX_BOT_STARTUP.md`；
  指定 `MC_PORT` 时「找到 MC 服务器」的替代信号是「[端口] 使用 .env 指定端口: 25565」

## 模型与思考强度（老板 2026-09-02 起，决策 #47）

每轮 `给CC.md` 头部有一行「**建议模型 / 思考强度 / 是否 ultracode**」，由开发按本轮复杂度标注，原则**该花就花、能省就省**。老板起会话时照它选（`claude --model … --effort …`，或会话里 `/model` `/effort`；ultracode 按老板的开法）；多步任务可写成分步切换。你开场把**实际运行的模型/强度/是否 ultracode**写进反馈头部（不确定就写 UNKNOWN），任务书没标的按「常规」档、不开 ultracode。

| 档 | 什么活 | 模型 | 强度 |
|---|---|---|---|
| 机械 | 归档、看板补录、文档补行、只加日志、零冲突预期的快进 | Sonnet 5 | `medium` |
| 常规 | 根因已钉死的最小补丁 + 单测；按清单跑真机；小范围设计 | Opus 5 | `high` |
| 疑难 | 根因未知要取证、多文件合并冲突、时序/并发类 bug、跨模块改动 | Opus 5 | `xhigh` |
| 极难 | 多小时自主真机施工带多套判据且随时要现场判断、长程调查、Opus xhigh 仍拿不下的 | Fable 5.1 | `high`（必要时 `xhigh`） |
| 极难+ | 上一轮 `xhigh` 已取证一次仍 UNKNOWN 的根因、跨多模块的时序死结——**证据齐了还想不通**才用；证据不够的 UNKNOWN（缺日志）先加日志，升档没用 | Fable 5.1 | `max` |

**ultracode（老板 2026-09-05，决策 #77 / #79）**：CC 会话里的多子代理并行模式，是**第三个旋钮**，与档位独立。任务书按步标三档：**可开**（CC 自判；若不开，在反馈头部写一句为什么——例如「一支探针一次扫完比撒子代理更硬」）/ **必开**（必须开）/ **不开**：

| 开 | 不开 |
|---|---|
| 普查、清账（多份图纸 / 多处旧改动逐个核） | **真机轮**（一只 bot 一台服务器，串不开；多路盯同一份日志没意义） |
| 全量日志复盘（逐条配位置算距离、按 owner 排时间线） | 根因已钉死的最小补丁 + 单测 |
| 一轮多个独立根因分头取证（各读各的模块） | 归档、看板、文档 |
| 大合并撞车：多文件冲突各自解、再统一跑测试 | 一人能一口气读完的小取证 |

开了 ultracode 也**照旧**：一轮一根因、地盘不变、子代理的结论同样标 已证实 / 合理推断 / UNKNOWN、汇总时写清哪条是谁查的；子代理跑测试/探针会占 CPU，真机线在跑时别开。

同一轮里先难后易的，任务书会写「第 N 步起切 …」；轮中冒出任务书没料到的新根因，可临时升档取证，取证完切回。

**模型不按线钉死**：三条线没有固定模型，每轮按当轮任务的复杂度和当时情况单独定；老板是 Max 计划且有 Fable 用量，**Fable 是正常选项，不是例外**——根因未知、大合并撞车、长程调查、无人值守的长真机这类活，该上就上。
