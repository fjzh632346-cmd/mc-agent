## 硬规矩（后勤线版）

- **永不进游戏**：不起服务器、不起 bot、不连任何端口。这台电脑 16G 内存，
  两条线的服务器已经占满预算，你这条线的定位就是零游戏开销。
  需要真机才能验的事，写进反馈交开发转给对应的线
- 代码与素材改动一律在 `D:\code\MC-ops` 做并提交到 `feat/ops`；
  主仓除上面两处特例外一个文件都不碰，`D:\code\MC-fix`、`D:\code\MC` 完全不碰
- **素材库红线**：`npm run syncCommunityBlueprints` 只许 `--only=<id>` 增量模式，
  **禁止全量**（解禁与否由建造线第 6 轮验证后宣布）；
  **禁止改动**别墅（在建）与城墙门楼（第 6 轮要用）的任何现有条目和缓存
- 一轮活干完就收，不顺手扩大范围；被禁 git 命令同主协议
- **兼职离线修缮（老板决策 #38，2026-09-02 起）**：可修不需要进游戏就能验证的执行层 bug
  （规划/顺序/状态类），标准同修缮线——一轮一根因、最小补丁、配单测、不降验收标准；
  连接层/逃生梯/寻路/箱子交互归修缮线，不碰；真机验证由开发转给带游戏的线
- **开工级离线探针必跑（老板决策 #105，2026-09-13 起）**：`node scripts/offline-build-start-probe.js`（MC-ops，后勤 21 交付）
  在两种情况下必跑并把「说法→路径」表贴进反馈：①每次新图纸入库或改图纸——新图纸那一行须 ✅ 且走的路符合预期，
  其余行与上一次比路径/成败逐字不变；②每次 `feat/ops` 合回主干前（合并轮由建造线跑，结果写进建造反馈）。
  **新入库的本地定稿图纸必须带 `metadata.complexityTier`（老板决策 #104）**，否则会静默走回社区样板路
- `feat/ops` 合并回主干单独开轮，最多攒 2–3 轮合一次
