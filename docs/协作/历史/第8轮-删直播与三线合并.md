## 需要老板拍板的问题

### 问题 1：骷髅头朝向走「修理」还是「豁免」？

- 背景：上轮发现放骷髅头时朝向控制不了，导致一次任务失败。这次分析清楚了：朝向由放置瞬间她脸朝的方向决定，代码完全可以在放之前让她先转身——这是能修好的毛病，不是游戏规则死结。
- 选项 A：**修**。让她放这类方块前先按图纸要求转身。代价：修缮线或建造线一轮的小改动+测试；好处：骷髅头、旗帜等所有带朝向的装饰一劳永逸，验收标准一寸不松。
- 选项 B：**豁免**。把朝向差异列入不比较清单。代价：验收标准实际放宽了一项本可以做对的东西，和「忠实还原以机器人可控部分为边界」的原则相抵触；好处：零开发。
- 我的建议：**A**。它和草皮的性质不同：草皮是游戏规则强制退化、谁也拦不住，豁免有理；朝向是我们自己没去控制，能做对的事就该做对。

### 四、第 3 步②：骷髅头朝向分析（结论：建议修，不建议豁免）

- **机制（已证实）**：skull/head 是 rotation 0-15 十六向方块，其值由**放置瞬间玩家 yaw** 决定。上轮失败例 `place_failed:state_mismatch:rotation:15!=4` 即她放置时没按图纸要求的朝向转身
- **与草皮的本质区别**：草皮退化是服务器 tick 强制行为，放对了也保不住（上轮 795 次实证）→ 豁免有理；rotation 放对了就**永久保持**，游戏不会改它 → 属「机器人可控」范围，按「忠实还原以可控为边界」原则**不该豁免**
- **修法（供修缮线/拍板后实施）**：放置前由期望 `rotation` 反解 yaw（rotation×22.5° 换算，注意 rotation 0 = 南、与 yaw 原点的偏移）、`bot.look(yaw)` 后再放；同类受益：旗帜、各色 head、可能还有 armor_stand 类。回归风险低（只在待放方块带 rotation 状态时多一步转身）
- 若老板仍选豁免（选项 B）：加一行 `isComparableStateKey` 排除 `rotation` 即可，但我不建议（理由见拍板问题 1）
