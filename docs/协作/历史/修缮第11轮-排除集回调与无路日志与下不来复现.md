## 白话摘要

她每次要走去某个地方之前，会带两份清单：一份写「只准在这几格垫脚」，另一份写「这几格是图纸要盖的，绝对不许往里塞垫脚石」。上一轮修的是第一份，这一轮修的是第二份，毛病一样：核对的时候看的是她要**踩进去**的那格，而不是垫脚石**真正落下**的那格。后果有两面：一面是她明明能过去，却因为要踩的那格恰好是图纸格，整条路被判成走不通；另一面更要紧——真要往图纸格里塞垫脚石的时候，这份清单**一声不吭**。我专门做了一次对照来证明这一点：只留这份清单、把另一道关卡撤掉，她当场就把垫脚石规划进了图纸格里。所以这份清单是白背的，撤掉它不但不会放松约束，反而把误伤去掉了；真正管用的那道关卡一直都在，改完之后它照样把往图纸格里塞垫脚石的路一口回绝。

第二件事是给她加了一句自述。以前她算不出路的时候一声不响，只表现为「人站着不动，然后超时」，上一轮为此猜了两个小时。现在她会直接说一句「我算不出路，目标是哪里，两份清单各有几格」。这句话当天就自己证明了价值：真机上第一次跑，四行自述一出来就告诉我卡点根本不在清单上（两份都是空的），省掉了整轮瞎猜；第二次跑另一个毛病，它又一次一句话点破。

第三件事是把「她站在楼上、箱子在地面，够不着」这个老问题在真机上复现出来了，而且原因彻底坐实：她走去开箱子这条路**既不许挖、也不许垫**，而找路的规矩里「往下跳」最多只允许四格；这次她站的塔顶比箱子高六格，所以一步都下不来。更要命的是失败之后的那套自救——它只会在**同一个高度**上左右挪四格再试一次，从设计上就不可能把人送下去，真机日志里挪完还是算不出路，一字不差。这个不用修，先记下来，修法有三条备选。

**没做成的一件事**：第 1 步这个毛病，我没能在真机上摆出「改前失败、改后成功」的对照靶子。原因不是修得不对，而是这个毛病要发作，必须让她**踩进一格图纸上有、但还没盖起来的格子**，而脚下那格又不能是图纸格；现在世界里现成的两个建筑都太小（最宽七格），她站在边上伸手就够得着中间，压根用不着搭桥。要摆出这个靶子得先专门盖一座十一格以上、带悬挑的建筑，那是另一轮的活。离线那边的证据是完整的、而且用的就是她真身那套找路程序，所以修复本身我判已证实；真机这一侧我如实标 **未验**。

### 二、第 1 步：排除集回调同样记错格

#### 2.1 病灶（已证实，读码）

`actions/move.js` `addScaffoldPlacementExclusions` 里，排除集（`reservedPositions` + `scaffoldExclusionPositions`，即图纸正式目标格 + 当前目标）曾经既走**代价回调** `exclusionAreasPlace`，又走**邻居过滤器** `installScaffoldPlacementCellFilter`。
上游 `node_modules/mineflayer-pathfinder/lib/movements.js:382` `getMoveForward` 的搭桥分支：

```js
cost += this.exclusionPlace(blockC)                                   // 记的是「走进去」的格
toPlace.push({ x: node.x, y: node.y - 1, z: node.z, dx: dir.x, dy: 0, dz: dir.z })  // 真正落块 = blockD
```

代价记在 blockC（她要踩进去的格），块却落在 blockD（她要垫的那格）。所以这条回调**两个方向都是错的**：

- **误杀**：她只是要**路过**一格图纸格，脚下那格根本不是图纸格，桥步照样 +100 → `cost > 100 return` 丢弃 → 预演（不带回调）算得出、执行算不出 → 站着不动到 `move_timeout`
- **漏防**：真要把垫脚石落进图纸格的那种桥步，被记分的是 blockC 而不是那格，**回调一分不扣**

对照 `getMoveJumpUp`（`:331` 记 blockD、`:341` 记 blockC，两处都与各自 `toPlace` 对得上）和 `getMoveUp`（`:547`），只有 `getMoveForward` 这一处错位——这也再次解释了「垒柱、跳上去都行，唯独搭桥不行」。

#### 4.4 第 1 步真机靶子为什么没做成（如实写，**未验**）

试了三种靶子，都没能把这个毛病逼出来。根本原因是这个毛病的**发作前提**很苛刻：她必须**踩进一格「图纸上有、但当前还是空气」的格**（这样它才既在排除集里、又能走进去），而**这一格的脚下那格不能是图纸格**（否则过滤器本来就该拒，改前改后都 `noPath`）。

3. **改用 5×5 围栏当靶子**：几何上算死了不可能——16 格围栏是单层小环，摆放伸手距离 4.5 格，从环上任何一个能站的点都够得到全环，她根本不需要搭桥

**机制（已证实，读码 + 上面的日志两头对上）**：

| 项 | 事实 |

| 是「没有下行手段」而**不是**「有手段没启用」 | `actions/storage.js:47` `moveToChest` → `moveTo`，`canDig: options.canDig === true`，而 `:159` `openChest` 那个调用**不传 canDig** → **false**；也不传 `allowScaffolding` → `resolveMovementProfile` 默认 false，连带 `allow1by1towers` false |
