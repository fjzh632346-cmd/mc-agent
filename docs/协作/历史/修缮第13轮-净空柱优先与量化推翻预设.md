## 一句话结论

原以为「让她优先站有地板的地方」能省事，一量才发现门楼那两盏灯笼四周**根本没有一处有地板的落脚点**，所以那个改法一点用没有；真正决定成败的是「她被掐断之后，从哪几个位置里挑四个重算」——原来的挑法在这两盏灯笼上四个名额全押在同一堵墙下面、正好漏掉唯一算得完的那个，改成先挑「脚底下能一根柱子直捅到地」的位置后，两盏灯笼都从「挑不中」变成「挑中」，而已经验过的靶子一个都没变坏。

## 白话摘要

她要在高处放东西时，会先列出几十个可能的落脚点，挨个飞快试算一遍；试算不完的，第 12 轮已经让她再挑最多四个多算一会儿。这一轮本来是想让她列名单时先把「脚底下有地板」的排前面。我把门楼那份完整的施工存档在电脑上原样重演，按第 12 轮校准好的真机速度算了一遍，结果是：门楼还剩的那两盏灯笼，四周三十多个落脚点**没有一个脚底下有地板**，全是悬空的，所以「有地板的排前面」这条改法在那儿等于什么都没做；而且她第一遍本来就会把每个落脚点都试一遍，谁排前谁排后不影响结果。

真正卡人的地方在后面那步：三十多个全被掐断之后，只有一个位置是真能在补算时限内算完的，而原来的挑法按「算到哪儿离目标最近」排，四个名额全给了挤在同一处的四个邻居，唯独漏掉那一个。我把判据换成一句更贴近实情的话——**她要爬上去靠的是从脚底下往下垒一根柱子，那就看她脚底下到最近一层实地之间有没有被挡住**。换完之后两盏灯笼的四个名额全给了「柱子能直接垒上去」的位置，那个唯一算得完的都被挑中了；同时第 12 轮验过的两座靶塔（高十一格、高七格）一个都没变差。列名单时也照任务书要求做了同样的分区，悬空的一个没删，仍然当保底。

真机上：新判据在游戏里算得对、日志里能一眼看出来（会写明有几个「柱子通」的、四个名额分别是哪种）；从零盖一整栋小屋一百八十四步照样一次盖成，完全没触发补算；高七格那条临界线和第 12 轮逐字一样。另外把第 12 轮欠的那笔账补上了：正常难度下她从六格高跳下去，血从二十掉到十七，正好是书上算的数。

有一处要说清楚：同一座靶子、同一个距离上做的一对照，改前那次她选了紧贴墙的那根柱子、爬上去了；改后那次她选了离墙两格的那根、爬到一半超时没爬上去。这不是挑错了种类（两根都是「柱子能通」的），是这两根之间还得比「哪根好爬」，而补算一找到能走的就停、根本没机会比。后来又跑了两次改后的，都选了贴墙那根、都成功。这条我记进了候选池，没有顺手改。

**2.3 结论一句（任务书第 1 步要的那个数）**：**改候选排序 / 分区能把「第一遍就有方案」的比例从 0 提到 0。** 两条独立的理由：

1. **第一遍的顺序不影响结果**。`planControlledVerticalAccess` 的第一遍把 `candidates.slice(0, maxPreviews)`（默认 48）**逐个**预演，每个用自己按直线距离算出的片数预算（`controlledVerticalAccessPreviewSliceBudget`），中途不 break（`if (extended && plans.length > 0) break` 只对补算生效）。三个目标的候选数是 14 / 32 / 33，都没到 48，**全部会被预演**，谁前谁后不改变 `legal` 的个数。
2. **「脚下实心」这个键在这类几何里没有可提拔的对象**：生成候选 0 / 20、0 / 32、0 / 33；把窗口放宽到 `target−1` 也只多出 `604,76,0` 一个，而它本来就在限制集里、并且是**最贵**的那批（51 片，预算 11）。反过来，`604,77,-2` 上第一遍唯一算得最快的两个恰恰是脚下空 8 格的 `608,75,-2`（25 片）和 `604,75,2`（26 片）——**「脚下实心」与「便宜」在这里是反相关的**。

**2.6 那两个「算得完」的候选到底特别在哪（已证实）**。`604,80,3` 与 `604,80,-19` 的共同点是**脚下到最近一层实地之间没有任何东西挡着**（落差 13，一根直柱子从地面垒上去就到）；算不完的那些，脚下 1–7 格处压着东西。`probe-column.js` 查明挡路的是什么：**`stone_brick_slab`（板砖台阶）**、`redstone_wire`、`comparator`——都是「非空气、又不能站人」的薄块。这就是机制：**悬空站位只能靠垒柱子上去，而柱子只能沿一根没被挡住的竖列往上垒；列被挡住的站位只能绕着障碍从侧面接近，那正是把片数烧光的那种搜索。**

所以本轮把「不查脚下」这条池项落成了它该有的样子：不是问「我脚底下正好有没有地板」，而是问「我脚底下有没有一根通到实地的净空柱」——落差 0（有地板）只是它的一个特例。

### 五、真机踩的坑（记池 / 给做夹具的人）

1. **`Start-Process` 起的 bot 会无预警消失**：`before` 那个 pid 跑了约 20 分钟后进程没了，`.err.log` 无任何异常栈、服务器 `list` 变 0 人。重起即可，但长跑的夹具要在每步之间确认它还在（`grep 上线成功` + `list`）。
2. **一座夹具塔只够跑一趟**：目标砖一盖上 run 就 `COMPLETED`，下一句「建个围墙」会**在她当前位置新开一座**（第一次撞到时她跑去 700,100,313 另起了一座）。所以每个 case 都要 `prep` 一次、换一个 origin。
3. **「用板砖台阶做遮篷挡住竖列」会适得其反**：台阶本身能站人，等于给被挡的站位送了一个起跳平台，路反而更便宜（那次跑下来第一遍就 `legal=14`）。要造「挡住且不能站」的层，得用栅栏那类峰高 1.5 的方块（单测里用的就是栅栏）。
4. 真机吞吐**跑与跑之间有明显方差**：同形状同距离（W=20）的两次，一次 29 个全截断触发补算、一次第一遍就 `legal=13`。所以任何「第一遍有没有方案」的真机判据都要多跑几次，离线校准回放才是稳的那一头。
