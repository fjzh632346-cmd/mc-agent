### 一、第 1 步：接线设计（四问四答）

#### 1. 透传路径 + **续建取回的步会不会丢声明：不会（已证实，单测钉住）**

链路：`planBuildOrder()` → `preview.orderPlan.steps` → `session.steps`（`building-system.js:323`）→ 执行时 `placeOptions`（`:2682-2726`）→ `placeBlock(context, position, blockName, options)` → `placeBlockAgainstReference()`。中间只有 `placeOptions` 这一处是「一个字段一个字段显式写」的，所以断点只有它。

续建那条：`applyConstructionExecutionStepsForRun()`（`:7269`）拿**重新编译出来的** `preview.orderPlan.steps` 当 runtime 步，与存档 `run.steps` 走 `mergeRuntimeAndStoredSteps()`（`:7874`）。两处关键写法都是展开：

- `normalizeRuntimeConstructionStep()` → `{ ...step, … }`
- `hydrateRuntimeStepFromStoredRunStep()` → `{ ...legacy, ...runtimeStep, … }`，**runtime 在后**

所以声明是 runtime 步上的字段、每次重新编译都会重新长出来，**存档里根本不需要存它**，续建重放时一定吃得到。单测 `testDeclarationSurvivesResume` 用门楼那一格的真 step id + `status: state_repair` 的存档步跑了一遍，声明逐字还在。
反向也钉了：一个**只有存档、没有 runtime 对应**的孤儿步（`legacyStepFromStoredRunStep()` 是显式字段列表）**不带**声明，也不会凭空长出来——这是对的，那种步本来就不在本次图纸里。

#### 2. 参照选择（两条方案见上「与任务书不同的地方」）

#### 3. 临时砖 + **白名单会不会拦图纸格：会，本轮在放置侧自己破例（已证实）**
