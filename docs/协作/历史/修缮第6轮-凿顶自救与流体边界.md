## 白话摘要

上一轮我复现出来的那个坑，其实是个**有盖子的地洞**。她掉进去以后，五种自救办法轮着试一遍全没用——唯一真能把人抬上来的那招是"往脚底下垫方块、边垫边往上跳"，可头顶顶着一层石板，她根本跳不起来。上一轮我做过对照：同一个洞，只把盖子掀掉，她一秒钟就出来了。差别就在那块盖子。

这一轮就补这一件事：**要往上垫之前，先看一眼头顶。头顶那格挡着，就先把它凿掉。** 别的四种办法一个字没动。

真机上用**和上一轮完全一样的洞、一样的脚本**跑：上一轮她试遍五招后放弃，人还在洞底；这一轮她凿掉一层盖子、垫了三块方块，爬到地面上了。头顶本来就开阔的普通坑我也复跑了一次，行为和上一轮**一模一样**——凿顶那段代码连一行日志都没打，等于没参与。

安全边界是这一轮真正花心思的地方，因为凿头顶天然危险。我没有另写一套判断，而是直接用了工程里原本就有的那个"这块能不能安全地挖"的检查——它本来就会看目标方块**周围一格**有没有水或者岩浆。于是"盖子上面压着水就别凿"这条规矩是白拿的，不是我新发明的。我在真机上专门造了一个"盖子上面盖着一池水"的场景验证：她**没有**下手，日志里明明白白写着"顶上有水，不凿"，然后规规矩矩停在原地等人——人是干的，没淹死。

除此之外还有四道拦阻，都配了测试：基岩这种凿不动的不试；区块没加载、根本没看见的方块不动它（沿用上一轮定下的规矩）；别人盖好的房子的屋顶绝对不凿；盖子太厚有个上限（三层），再厚就不是陷阱是溶洞了，硬往上打洞本身就是另一种死法。

### 二、根因回顾与方案选择（已证实）

第 5 轮的对照实验已经把因果钉死，本轮不再重复论证，只复述结论：

```
带顶空腔（y62–63 净空 2 格，y64 一层壳）
  repath        → no_safe_player_point
  jump_and_step → ESCAPE_RUNG_NO_PROGRESS（顶着盖子跳不动）
  nearby_exit   → move_timeout
  safe_dig      → 挖 614,62,401（同层侧壁）→ move_timeout（洞更大了，人还在里面）
  pillar_up     → place_failed / pillar_jump_did_not_clear   ← 唯一能救人的那档，死在这里
  safe_posture  → 停住等人
```

物理上的原因很精确：她身高 1.8，脚在 `y`、头顶在 `y+1.8`；盖子底面在 `y+2`，
所以起跳最多升 0.2，而 `waitUntilAirborne` 要求升到 **0.55** 才算"身体离开了要填的那格"。
差的就是这 0.35。

**做成 `pillar_up` 的前置，不新开一档**（任务书授权"按改动面最小的方式定"）。理由三条：

1. 失败是 `pillar_up` 自己的失败，修在自己家里，**其余四档零改动**——本轮红线的第一条
2. 独立成档的话，"凿穿盖子"本身产生的位移增益是 0，会被 `measureEscapeProgress`
   判成 `NO_PROGRESS` 记为失败并写进 `exhausted`——**一件对的事被记成错的**，
   下次同一地点还会被 ledger 跳过。语义是坏的
3. 厚盖子需要**每垫一层就再凿一层**，天然属于垫方块的循环内部，不是循环外的一次性动作

### 三、补丁（已提交 `a044997c`，显式 3 个文件）

新增 `clearHeadroomForLift`（`tasks/stuck-recovery.js:404`），在 `attemptPillarUp` 的
垫方块循环里、`placeUnderfoot` **之前**调用（`:521`）；配套 `ceilingRefusalReason` 只负责起名。

**复用而非另造**——这是本轮最关键的设计决定：

| 复用的件 | 用途 |
|---|---|
| `isDigSafe`（本文件既有） | **决定能不能凿**。它本来就拒绝受保护方块、岩浆、火、仙人掌、水，并且 `localBlocks(pos, 1)` 的 `dy` 扫 −1…+1，**天然包含盖子上面那一格** |
| `checkProtectedBuildingDig` + `resolveRegionOptions` | 别人盖好的房子的屋顶不凿；**和垫方块那半边读同一个 region 来源** |
| `AIR_BLOCKS` / `DANGER_BLOCKS` / `WATER_BLOCKS` | 起名用，不重复判断逻辑 |

"盖子上面有流体就不凿"这条**是白拿的**，不是我新写的规则——
`ceilingRefusalReason` 只是把 `isDigSafe` 已经做出的否决**翻译成人话**，
刻意放在它旁边并写明"决定权在 isDigSafe"，防止两者日后各说各话。

**五道拒绝，逐条有测试**：

| 情形 | 行为 | 失败名 |
|---|---|---|
| 盖子上面/本身是水或岩浆 | 不凿，`pillar_up` 如实放弃 | `water_above_ceiling` / `lava_above_ceiling` / `fluid_or_danger_ceiling` |
| 基岩等 `diggable === false` | 不凿 | `undiggable:<name>` |
| 已完工建筑的屋顶 | 不凿 | `protected_building:<runId>` |
| 盖子超过 3 层（`maxCeilingDigs`） | 凿满 3 层后停手 | `ceiling_too_thick:3` |
| 挖完读回去还在（挖成功是假的） | 不继续跳 | `ceiling_still_blocked:<name>` |

**两处"什么都不做"**（零变化的那一半）：

- 头顶那格是空气 → 直接返回 `ceiling_open`，**连日志都不打**，一行新代码路径都不走
- `blockAt` 返回 null（区块未加载）→ 返回 `ceiling_unknown`，交给起跳去判定，
  与改动前**逐字相同**。沿用第 5 轮定的规矩：**没看见的方块不作数**

另有开关 `allowCeilingDig: false`，关掉即完全回到第 5 轮行为（含在盖子下失败）。
预算 `{ dug }` 是**整次攀爬共用一份**，不是每层一份——两层盖子花两次。

失败原因也从原来那句含糊的 `pillar_jump_did_not_clear` 变成了
`pillar_ceiling_blocked:water_above_ceiling:stone` 这种一眼能读的。

### 四、单测 `tests/escape-ceiling-dig.test.js`（15 条，已进日常清单）

夹具 `createRoofedCavity` 自带一个**会拒绝起跳的物理模型**：
`setControlState('jump', true)` 会去查脚上两格是不是空气，不是就**不抬高坐标**。
这一条是整套测试的地基——换成"总是能跳"的假物件，下面每一条都能在没有补丁的情况下通过。
夹具用一份可变的世界 Map，凿掉又垫回来的格子读回的是**当前**的方块
（第一版用"挖过"和"放过"两个数组，挖过优先，结果垫上去的方块读回还是空气，
攀爬爬到一半自己踩空——这是夹具的 bug，已修）。

正向 3 条：单独调用凿掉正确的那一格并计预算 / 端到端从带顶空腔爬出且只凿一层 /
两层盖子每层一凿。
拒绝 6 条：顶上有水、顶上有岩浆、盖子本身是岩浆、基岩、预算封顶、挖了却没变空。
异常 1 条：挖抛异常要如实上报不能吞掉。
**零变化 3 条**：头顶开阔时不凿且**一行日志都不打**、未加载读到 null 不凿、显式关闭即回到旧行为
（并断言旧的失败名 `pillar_jump_did_not_clear` 原样重现）。
源码护栏 2 条（同一用例内）：清头顶必须在 `placeUnderfoot` **之前**；
安全判断必须仍然委托给 `isDigSafe`，不许被就地重写。
