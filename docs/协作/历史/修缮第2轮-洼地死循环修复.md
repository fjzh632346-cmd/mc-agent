## 一句话结论

掉进坑里出不来那个把林夏害死的毛病修好了：她现在会一级一级换招自救，实在不行就垫方块把自己顶出去，真机上四格深的坑四下就爬出来了；招数用尽时会停下来喊人，而不是原地打转到死。

## 白话摘要

先把病复现了：把她扔进一个自己挖的坑里，她果然又开始了——每半分钟重来一次，每次都从最没用的那招开始试，一模一样，永远试不到有用的招。查出来的原因有两层。一是她的"脱困记性"记在任务本身上，而上头每次失败都给她重新派一个新任务，记性跟着清零，所以永远从第一招重来。二是判定太宽松：只要挪动了一下就算脱困成功，哪怕只是在坑里横着挪了两格，于是连升级的机会都没有。

改法是给她做了一本随身的账，记着"这个地方哪些招已经证明没用"，这本账不随任务作废。判定也改成看有没有真的离开困住的那个位置，横挪两格不算数。另外补了两招她本来就缺的：垫方块把自己顶上去（真人玩家都会的那招），以及实在不行就停下别乱走、报出坐标喊人来捞。重试间隔也从死板的半分钟改成越失败等得越久、最多一分钟，免得她在危险地方反复折腾送死。

真机上验过了：四格深的坑，她垫了四块土就爬出来，爬到跟地面齐平就自动停手，不多浪费方块。身上没方块的时候，她按设计停下喊人，不再打转至死。有一点要说明：爬出来之后她往家走的路线又从坑口上面经过，一脚踩空掉了回去——这是另一个毛病（找路时不认得要绕开坑），不在这轮范围内，已经记进候选池。但关键区别是，掉回去以后她重新从头升级、而且带退避，不是过去那种一直重复到死。

## 需要老板拍板的问题

### 问题 1：爬出来之后又走回坑里，要不要当下一轮的主活？

- 背景：这轮修的是"掉进去出不来"，已经修好。但真机上看到她爬出来以后，往家走的路线又从坑上面经过，一脚踩空掉回去了。这是找路时不认得"这里是个坑、得绕开"，跟原来那个死循环是两回事。掉回去之后她会重新自救、不会再卡死，但会来回折腾。
- 选项 A：**下一轮就修这个**（找路时把已知的坑当障碍绕开）。（代价：推迟原定的清障盲走；风险：低，跟这轮改的是同一块地方，手还热，复现场也现成）
- 选项 B：**按原计划先修清障盲走**，这个排后面。（代价：她在坑边会来回几趟才走对；风险：低，已经不致死了）
- 我的建议：A。这两个其实是同一段路的两半，趁复现场还在、代码还热一起收拾干净，比隔两轮回头再来省事。

### 问题 2：垫方块这招在极深竖井里还不够稳，要不要单独打磨一轮？

- 背景：四格深的坑（也就是害死她那种自然洼地）四下爬出，稳定。我另外挖了个十格深的竖井试极限，她垫到七八格时会从自己垒的柱子上滑下来，最后没爬上去，按设计喊人收场。原因是垫的过程中身子会一点点飘出那一格。
- 选项 A：**先不管**。真实地形里十格深的竖井基本是她自己挖矿挖出来的，遇到就喊人。（代价：极端情况要人捞一把；风险：低，不会死）
- 选项 B：**单独花一轮打磨**垫方块的稳定性。（代价：一整轮只为一个边角情况；风险：低）
- 我的建议：A。害死过她的那种坑已经能自己出来了；极深竖井罕见，而且她不会死，只是要人搭把手。

### 二、根因（已证实，两层）

1. **脱困台账建在任务实例里**：`tasks/return-to-base-task.js:16` 构造函数里 `createRecoveryState()`。
   生存系统每次失败重建任务（节奏由 `systems/survival-system.js` 的 30 秒冷却决定），
   于是 `recoveryAttempts` 永远是 1，梯子永远从第 0 级重来。
   `canAttemptDigRecovery` 里那些按 attempts 递进的门槛因此**永远够不到**。
2. **成功判定只看 `moveTo` 的返回值**：`jump_and_step` 在坑里横挪 2 格也返回 ok，
   `finishRecovery` 随即把 stuckTicks / isStuck 全部清零，连本轮之内的升级都被切断。

顺带确认（**已证实**）：`bot.js:824` 的 `LEGACY_ESCAPE_DEFERRED` **不是**病因。
它只是"跟着 action 玩家跑"，被 managed task 占着 movement 锁而正确让位，不该动它。

### 三、修法：`tasks/escape-ladder.js`（新增，可复用）

台账按 key 存在 blackboard 的 `recovery.escapeLedgers` 上，**活得比任务实例长**：

| 字段 | 作用 |
|---|---|
| `exhausted` | 这个地方哪几级已被证明没用 |
| `anchor` | 卡住时的坐标；离开它才算脱困 |
| `nextAttemptAt` | 退避到期时间 |
| `gaveUp` | 已放弃，保持安全姿态 |

- 梯级：`repath → jump_and_step → nearby_exit → safe_dig → pillar_up → safe_posture`
- **成功判定改为"有没有离开锚点"**（爬高 ≥2 格或平面走出 ≥6 格），横挪不算
- **退避** `0/5/15/30/60` 秒封顶；退避窗口内直接保持安全姿态，不再空跑整轮梯子
- **暂时性失败不永久淘汰该级**（`no_pillar_material`、锁占用等）——
  否则"给我点方块"那句求助就是空话。有单测钉死这条
- 台账在**离开锚点后自动清空**，陈旧的"已放弃"不会困住已经脱身的 bot
- 三个会卡住的任务都接了 key：`return_to_base` / `return_to_player` / `follow`

新增两级（`tasks/stuck-recovery.js`）：

- `pillar_up`：垫方块爬出。**只放不挖**；每格先查 `findProtectedRegionAt`，
  落在保护建筑范围内直接放弃该级（有单测：一块都不许放）；只用 dirt/圆石/木板一类
  消耗品，不动贵重方块；爬到高过四周围墙就停手，不多浪费方块
- `safe_posture`：停 movement、清所有控制键、播报坐标求助。
  **它是终点不是脱困**——早期版本把它当成功，一轮结束就清台账，梯子又从第 0 级重来。
  这个坑我踩了，已钉上单测

**没有改动**：仲裁层、生存系统的 30 秒打断冷却、TaskManager。第 5 轮验过的保命行为一行没动。
