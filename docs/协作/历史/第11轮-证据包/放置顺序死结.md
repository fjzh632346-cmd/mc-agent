## 1. 现象一句话

轴向方块（`dark_oak_log[axis=x/y/z]`）必须点在**同轴**的相邻方块的面上才能放出正确朝向；门楼蓝图里一批这样的梁柱在施工序列里排在它们的同轴邻居**前面**（或根本没有同轴邻居），每次走到那一步就 `stateful_axis_no_y_reference` / `no_x_reference`，任务失败；保姆脚本重发后从存档续建又走到同一步，再失败——**同一坐标连续失败 3–5 次**（见 §3）。第 11 轮最后是用 RCON 守护式 setblock 把 133 根原木直接补上才过去的（清单见 `手术代放清单.txt`）。

## 2. 机制（代码，均 **已证实**）

- 轴向方块的参照物筛选：`actions/build.js:3136-3147` —— 只保留「参照物→目标」的面所在轴等于 `states.axis` 的参照物；没有就返回 `stateful_axis_no_<axis>_reference`。
- 失败后允许尝试临时参照物：`actions/build.js:3196-3201`（`canRetryStatefulWithTemporaryReference`）→ `ensureTemporaryPlacementReference`（`actions/build.js:3408-3466`）。
- 临时参照物候选位置：`actions/build.js:3515-3527`（`temporaryPlacementReferenceOffsets`）——**axis=y 只允许「目标正下方」一个候选**；axis=x/z 允许左右/前后两个。
- 临时参照物要立一根柱子：`actions/build.js:3560-3610`（`temporaryReferenceColumnPositions`）——从候选格往下找 ≤8 格的实体基座，柱子经过的任何一格若是**蓝图保留格**（`isReservedPosition`）就 `temporary_reference_reserved` 失败。
- 临时参照物失败时，错误只挂在返回值 `data.temporaryReferenceError` 里（`actions/build.js:855-863`），**日志不打印**——所以日志里只看到 `stateful_axis_no_y_reference`，看不到它为什么救不回来。
- 「计划参照物修复」（`BUILD_PLANNED_REFERENCE_REPAIR_TRIGGER`）是另一套机制，只对 `place_failed:unstable_air` 触发（第 1 段日志 5 次触发全是 unstable_air，见 §4），对轴向原木从未触发。

**合理推断**（把机制套到失败坐标上）：
- 605,72,-4 / 605,72,-2 / 604,72,-16 / 603,72,-13 / 602,72,-12 / 606,72,-13（axis=y）：蓝图里上下都是空气（它们是横跨门洞的悬空梁），唯一候选「正下方」要在门洞里立 5 格高的柱子，而门洞格是保留格 → 临时参照物失败。
- 602,72,-3 / 603,72,-3 / 604,72,-3 / 603,72,-2 / 602,72,-1 / 606,72,-4（axis=y）：下方是空气（门洞），上方是排在后面的方块，且其中 3 处上方是**红石线**（不可点击）——即使先放了上面也没法用。
- 塔柱 601/602/606/607 × y76–78 与 600/602/606/608 × y79–82（axis=y）：柱子的底座（y75 / y78）在序列里排在柱子后面，见 §5.3。

## 6. 结论（给修缮线）

1. **已证实** 失败的直接原因是放置时同轴方向没有可点击的参照物；同一坐标在续建中反复撞到同一步（605,72,-4 ×3、602,72,-3 ×5、603,72,-3、603,72,-15、607,78,-12）。

4. **合理推断** 修法方向（供参考，不是任务书）：(a) 编译期按轴向依赖重排（同轴邻居先放，柱子从底座往上）；(b) 对蓝图里无同轴邻居的悬空梁允许在保留格里立**临时**柱并事后清除，或允许 axis=y 用上方参照物；(c) 把 `temporaryReferenceError` 打进日志；(d) 续建时对连续 N 次同点失败的步做跳过/延后而不是死循环。
