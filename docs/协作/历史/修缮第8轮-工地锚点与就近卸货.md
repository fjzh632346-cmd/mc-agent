## 一句话结论

## 白话摘要

她心里的「家」是一个死坐标：几个月前玩家站在某处说了一句「记住这里是基地」，从那以后再没有任何东西会更新它。工地后来搬到几百格外，可这个坐标没动，于是每次「背包满了该回家卸货」「离家太远该回去了」这两个念头一起，她就往那个几百格外的老地方走，工地丢下不管。真机上我把这一幕原样复现了：她背包一满就排队要走 557 格，前后一共发起了十三趟。

修法是给「家」加一个临时的、跟着工地走的位置：只要施工任务还活着，这个位置每半秒就更新成她当前站的地方；施工结束（哪怕是失败）之后再保留三分钟，因为人还站在工地上。在这三分钟里，「离家太远」这个念头根本不会冒出来；「背包满了」则改成就近处理——先找施工任务自己记的暂存箱，再找记忆里的箱子，最后现场扫一圈三十二格；找得到就去卸货，卸完接着盖；一个都找不到就原地站着报一声「我这儿没箱子」，宁可等人来也不跑丢。倒东西的时候还会把这一栋房子还要用的材料留在身上，免得刚倒进去下一秒又得取回来。

真机上还抓到一个额外的坑：她已经在往老基地走的路上时，玩家喊「盖房子」，这道命令会排在走路后面干等——因为系统认为「回家」比「盖房」更急。改前她带着这道命令又走了七十六格、一块砖没砌；改后玩家一喊盖房，那趟回家立刻作废，盖房马上开工。

保命那一条一点没动：血量危急、饿到掉血、附近有怪，照旧可以打断施工把她拉走——真机上她还真的因为血量危急撤退过一次，说明这条通路完好。另外留了一个开关，一句话就能整体关掉这次的改动、回到旧行为。

**为什么撤销要挂在指令那一侧（已证实）**：真机第一次改后跑，`[WORKSITE_RETURN_CANCELLED]` 一次都没打。
原因是 `TickLoop.updateOnce` 里 `await taskManager.update(...)` 会一直停在 return 任务自己的
`moveTo` await 上，`this.ticking` 保持 true，**生存循环在她走路期间根本不跑**——
直到 move_timeout 才恢复。所以撤销必须挂在聊天指令那条路上（它不经过 tick 循环）。
