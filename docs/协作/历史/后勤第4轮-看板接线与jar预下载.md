### 一、第 1 步：看板接回修缮线（本轮硬性交付，已完成）

#### 1.1 病根复述（第 3 轮已证实）

#### 1.2 改法

`dashboard/lanes.js` 重写，核心是三个新东西：

**（a）外部来源登记表**——授权范围就是这一张表，写死到文件级，不是目录级：

```js
const EXTERNAL_FEEDBACK = {
  '修缮': process.env.MC_LANE_FEEDBACK_修缮 ||
          process.env.MC_LANE_FEEDBACK_FIX ||
          'D:\\code\\MC-fix\\docs\\协作\\修缮\\CC反馈.md',
};
```

（留了环境变量覆盖：换盘符/换机器不用改代码，也方便自测时指到别处。）

**（b）`loadCandidate(file, origin)`**——读一个候选文件，`statSync`/`readFileSync` 全在 `try/catch` 里，读不到返回 `null`；读到了但**没有「轮次」字段**（指路条、退役线存档）也返回 `null`。原来那条「没有轮次就不算一条在跑的线」的规则原样保留。

**（c）`pickSource(main, external)`**——主仓与外部两份的取舍：

| 情况 | 取谁 |
|---|---|
| 外部轮次 > 主仓轮次 | 外部 |
| 主仓轮次 > 外部轮次 | 主仓 |
| 轮次相同 | 改得晚的那份（`mtimeMs`） |
| 只有一份有效 | 那一份 |
| 两份都无效 | 这条线不出现在看板上 |

另外两处配套改动：

- **主仓没有该线目录时也要出现**：`collectLanes` 里把 `EXTERNAL_FEEDBACK` 的键并进待扫线名（`for (const name of Object.keys(EXTERNAL_FEEDBACK)) if (!names.includes(name)) names.push(name)`）。这样将来修缮线把主仓目录整个删掉，看板照样有它
- **任务书标题只从主仓读**：外部来源胜出时 `taskTitle = null`。因为主仓的 `docs/协作/修缮/给CC.md` 现在是一张指路条，标题是「已迁移」，显示出来是误导；授权只有反馈那一个文件，不能去读 MC-fix 的任务书。宁可不显示也不误报
- 新增两个字段供排查用：`source`（`'main'` / `'external'`）、`sourceFile`（实际读了哪个文件）。`updated` 改成取胜出那份的 mtime
