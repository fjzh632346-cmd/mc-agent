## 需要老板拍板的问题

### 问题 1：升级前必须先装新版 Java，装不装、谁装？

- 背景：您已经拍板升级服务器。但新版本的游戏服务器有个硬性要求 —— 必须用 Java 21 才能启动，现在这台电脑上只有 Java 17（还有一个更老的 Java 8）。这不是可以绕过去的选项，是启动的前置条件。装这个是免费的、常规的，装完不影响现有的旧版服务器（两个版本可以共存，启动脚本本来就留了切换开关）。
- 选项 A：**装一份 Java 21**（推荐 Zulu 21，和现在那份 Java 17 同一家、同样的装法，装在旁边不覆盖）。代价：一次几分钟的安装；风险：很低，两个版本互不干扰。
- 选项 B：**先不装**，升级这条线整个往后放。代价：门楼这类新版本素材永远用不了，第二栋非住宅建筑的验收目标就一直悬着。
- 我的建议：**A**。这是整条升级路线上唯一一个「我做不了、必须有人动手」的环节，其余每一步两条施工线都能自己完成。**装软件这件事我不代劳**，请您或开发决定由谁来装。

### 问题 2：升到哪个版本？我建议 1.21.8

- 背景：能装下门楼那两百多块方块的最低版本是 1.21（也就是 1.21.1）。但我把素材库全体在四个候选版本上各体检了一遍，越往后能用的素材越多：现在的旧版本十一份用不了，1.21.1 剩六份，1.21.4 剩五份，1.21.8 只剩四份 —— 而且这四份坏的都是同一个「草改名」问题，加张对照表就全好。
- 选项 A：**升到 1.21.8**（我的建议）。好处：素材库全部可用，是这一代版本的收官版、稳定；代价：比最低要求多跨几个小版本，游戏内容变化更多一点。
- 选项 B：**升到 1.21.1**（最保守）。好处：跨度最小，只解决门楼；代价：本地素材仓库里那几份「浅色橡木」「萤火虫灌木」的素材还是用不了。
- 选项 C：升到更新的 1.21.11。代价：更贴近前沿、变化更多、实地验证更少，收益不明显。
- 我的建议：**A（1.21.8）**。它把「能用的素材」从八十五份提到九十六份（全部），而机器人这边不需要为此多做任何改动。

**步骤（按执行顺序，两条施工线各自照做）**

1. **装 Java 21**（一次性，全机共用）→ 拍板问题 1。装完两条线各自设 `MC_SERVER_JAVA` 指向它，脚本不用改
2. **备份世界**：升级前把整个 `world\` 目录复制一份到仓库外（如 `D:\code\MC-backups\world-pre-1.21.8-<日期>\`），163 MB，几秒钟。**这是唯一的回滚手段**
