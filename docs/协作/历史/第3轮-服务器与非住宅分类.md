### 二、第二步前置核查：换世界不会作废任何东西。已证实

**worldIdentity 的来源**（`systems/building-system.js:7726-7743` `getWorldIdentity()`）：

```text

worldId   ← context.worldIdentity（生产代码从未设置）|| 环境变量 MC_WORLD_ID || null
```

worldId 是**操作员在启动 bot 时通过环境变量提供的标签**，不从存档文件推导。48 条 run 里存的 `"worldId": "building-A:新的世界"`、`"identitySource": "MC_WORLD_ID"` 与 `_backups/post-fix-construction-world-identity-fda7041-*/BACKUP-MANIFEST.md` 的设计说明相互印证：该机制本来就是为"换会话/换承载方式"设计的，明确写着"LAN 端口只是会话变更证据，不属于世界身份"。

**兼容判定规则**（`systems/construction-run-store.js:363-403`）：run 有 worldId 而当前没有 → `world_identity_unverified` 拒绝；两边都有但不同 → `world_id_changed` 拒绝；run 没有而当前有 → 允许并升级。**因此服务器上起 bot 必须带 `MC_WORLD_ID=building-A:新的世界`**，带上则 48 条 run 全部维持可续建。

### 五、第四步：非住宅分类。已完成，矩阵 delta=0

**现状核查（探针，已证实）**：`BuildingHardGate` 对缓存里四栋全部放行；唯一拦截来自 `FaithfulCommunityValidator` 的 `minWidth` / `usableInteriorVolume`。分类只需接入后者。

**分类来源（调研结论）**：用**显式声明**而非结构特征推断——若按"没有室内空间就算非住宅"自动判，一栋导入残缺的房子会自动获得豁免，这是降标准漏洞。链路：

```text
sources.json 条目 "structureUse": "nonresidential"（人工标注，仅两栋 fort）
→ sync 写入蓝图 metadata.structureUse + 索引记录 structureUse
→ 候选对象透传（community-blueprint-index.js cachedSampleCandidate）
→ validator resolveStructureUse()：request > selected > blueprint.metadata，非法值/缺省一律 residential
```

**非住宅不是不检查**：仍强制 `minNonAirBlocks`、`minHeight`、`remainingScaffoldCount`（脚手架残留对任何建筑都是缺陷）+ `requireSourceMode` 溯源；WorldDiff 逐块对照（fidelity/present/extra/bounds shrink，`compareExpectedActual`）一行未动，对所有类型照常严格。宜居性十项（minWidth/minDepth/门/玻璃/层数/室内体积/密封/屋顶/垂直通道/功能方块）只对住宅生效。缺项提案（下一轮可加）：墙顶可行走性、门洞可通行性。
