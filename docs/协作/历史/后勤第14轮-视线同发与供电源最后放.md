**第二件（活塞朝向，本轮主活）**：任务书给的假设是「抬头这个动作压根没发出去」。我逐行读了那段代码，**这条不成立**，而且不成立两次：发不发包看的是「跟上一个包比有没有变」，所以强制转头下一刻照样会发；何况活塞这条路本来就没走强制那一档。真正的原因在时间线的另一头——**放对的两个都是刚走完位就放的，放错的两个都是走位超时后原地放的**。走位超时时，寻路的「停下」只是挂了个牌子，那个牌子要等她走到下一个路径点才生效；她正卡着走不到，于是寻路每五十毫秒就把她的头按回水平一次，连我们那八十毫秒的稳定等待都被压掉，十秒后服务器读到的当然还是平视。

改法不去跟它抢那一瞬间——抢不赢就是掷硬币。改成**把「我现在朝这边看」这句话排在「放这块砖」前面**，两句话在同一口气里发出去，服务器按顺序读，这一次放置就按我们要的角度结算，下一刻谁再掰都无所谓。这一条在离线做了反证：把这句话关掉重跑，放置前最后一条视角消息就是寻路那条水平的——正是真机症状本身。

### 二、第 1 步：视角没送到服务器（提交 `b058f9bb`）

#### 1. 假设：**证伪**（已证实，读码逐行）

`node_modules/mineflayer/lib/plugins/physics.js`：

```js
bot.look = async (yaw, pitch, force) => { … if (force) { lastSentYaw = yaw; lastSentPitch = pitch; return } await lookingTask.promise }
// updatePosition() 里：
const lookUpdated = lastSent.yaw !== yaw || lastSent.pitch !== pitch   // lastSent 是「上一个发出去的包」
if (positionUpdated && lookUpdated) sendPacketPositionAndLook(...)
else if (lookUpdated) sendPacketLook(...)
```

`lastSentYaw/lastSentPitch`（累加器）与 `lastSent.yaw/pitch`（**上一个包**）是两个东西。force 改的是前者，发包判断比的是后者——所以 force 之后下一个物理刻**照样会发**。假设不成立。

**而且这条路根本没走 force**：我第 11 轮给这七族的方向里写的是 `forceLook: false`，`lookTowardDirection` 传的是 `bot.lookAt(target, false)`（非强制、要 await）。

#### 2. 真正的根因（已证实，读码 + 与真机三条现象逐条吻合）

`node_modules/mineflayer-pathfinder/index.js`：

- `bot.pathfinder.stop = () => { stopPathing = true }` —— **只挂牌子**
- 那个牌子只在「走到下一个路径点」时被消费：`if (Math.abs(dx) <= 0.35 && … ) { … if (stopPathing) { stop(); return } … }`
- `monitorMovement` 挂在 `physicsTick` 上，路径还在就每刻执行到 `bot.look(Math.atan2(-dx, -dz), 0)` —— **俯仰被写成 0**

我方 `actions/move.js`（只读，未改）：走位超时走 `stopMovePathfinder(bot, scaffoldActivity.active)`，非脚手架场景第二个参数是 `false` → **只调 `stop()`，不调 `setGoal(null)`**（那个函数自己的注释就写着「stop() 是懒的」）。于是走位超时后旧路径还在、寻路继续每刻掰视线。

与真机三条现象对照：

| 真机现象 | 这条根因的解释 |
|---|---|
| 放对的两个是刚走完位就放 | 走位正常完成 → `goal_reached` → 路径清空 → 没人掰 |
| 放错的两个是走位超时后原地放 | 超时 → 只挂牌子 → 旧路径还在 → 每刻按回水平 |
| 十秒后服务器仍是水平 | 寻路一直在掰，不是一个刻的竞态 |

#### 3. 改法（最小，且不与任何人抢）

`actions/build.js` 新增 `placementLookAngles()`（照抄 `bot.lookAt` 的算法，含眼高，所以潜行时也算得对）与 `sendPlacementLookPacket()`；在 KEEP_YAW 段 `_genericPlace` **之前的同一个同步块里**写一个 `look` 包。两个包一起离开，服务器按顺序读，这一次放置就按我们的角度结算。写不出去（没有 client / 这个协议版本包结构不认）时记 `sent=false` 并**退回今天的行为**，不制造新失败。

新日志：`[BUILD_PLACE_LOOK_SYNCED] target=… block=… facing=… sent=true pitch=… yaw=…`
