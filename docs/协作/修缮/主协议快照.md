# 协作协议 · 建造线（固定，不要改动本文件的结构）

**你在 `D:\code\MC-blueprint-ir-v1`。这是建造线。**

本项目有三方参与：

| 角色 | 是谁 | 干什么 |
|---|---|---|
| **老板** | 项目所有者 | 拍板决策。不看代码，只看白话结论 |

老板**不再手工搬运任何内容**。三方全部通过 `docs\协作\建造\` 下的两个文件交换信息。

## 你每次会话必须做的事

### 1. 开场

```powershell
cd D:\code\MC-blueprint-ir-v1
```

按顺序读（**全部在本 worktree 内，不要去别的目录**）：

```text
AGENTS.md                  项目铁律，永远最高优先级
docs\协作\建造\给CC.md      本轮要你干什么
docs\协作\建造\CC反馈.md    上一轮你自己写的结果，看有没有未了结的
```

然后跑：

```powershell
git status --short
git log --oneline -10
git branch --show-current
npm test
```

### 2. 干活

严格按 `给CC.md` 的范围。它没写的不要做。

### 3. 收尾（这一步不能省）

把结果写进 `docs\协作\建造\CC反馈.md`，格式见下面第 3 节。

> **不要发链接。不要只在聊天里回复。不要新建别的报告文件。**
> 老板看不到你的聊天窗口，开发只读这一个文件。
> 写进文件了才算交付；没写就等于没做。

写之前：如果反馈文件里还有上一轮的内容，先整份挪到
`docs\协作\历史\第N轮-简短标题.md`，再重写。**历史目录只增不删。**

## 真机验收：专用服务器已建成，不再需要老板开游戏

第 3 轮已搭好本地专用服务器（`D:\code\MC-server\`）。

```powershell
# 启停
scripts\mc-server.ps1 start | stop | status

# 起 bot 必须带这两个环境变量
$env:MC_WORLD_ID = 'building-A:新的世界'   # 不带则 48 条施工记录全部认不出、无法续建
$env:MC_PORT = '25565'
```

- 起进程用 `Start-Process`，**不要用 `Start-Job`**（子进程会随工具会话被杀，已踩过）
- 停服务器必须走 RCON 优雅停，**不要杀进程**（会损坏世界）
- ONLINE-GATE 四信号见 `docs/CODEX_BOT_STARTUP.md`；
  指定 `MC_PORT` 时「找到 MC 服务器」的替代信号是「[端口] 使用 .env 指定端口: 25565」

### 三条硬规矩

1. **「一句话结论」和「白话摘要」里不许出现文件名、函数名、行号、英文术语。**
   这两段是给老板看的。技术内容一律放「技术细节」。
2. **每条结论必须标 已证实 / 合理推断 / UNKNOWN。**
   没证据就写 UNKNOWN，不要用「应该」「大概」「估计已修复」蒙混。
3. **卡住了就把状态写成「卡住了」并说清卡在哪。**
   不要为了让报告好看而把 FAIL 写成 PASS，不要隐藏 BLOCKED。

## 常驻红线（每轮都生效）

- 一轮只打一个根因；最小补丁；改代码必须配单测
- 不降低验收标准；不手改报告把 FAIL 变 PASS；不隐藏 BLOCKED
- 不重构 TaskManager；不做 `AGENTS.md` 第 10 节列的大改造
- 禁止 `git add -A` / `git add .` / `git reset --hard` / `git clean -fd` / `git stash` / `git checkout --`
- 提交必须显式指定文件；不提交生成的报告和 `data/memory/*`
- 工作区里若有别人的改动，**不要顺手清理或丢弃**
- `npm run syncCommunityBlueprints` **全量模式在工作区脏时禁止运行**
  （会重算山顶别墅、断掉在建的续建）。只能用 `--only=<id>` 增量模式。
  第 6 轮第 1 步做受控验证，通过后本条由你更新为解除。
  `.tmp/cache-backup-pre-sync-round3/` 的回滚备份在确认安全前不要删
- `docs/decision-needed.md` 只追加不清理，**不能当现状读**
- 不确定要不要做的事，写进「需要老板拍板的问题」，不要自己决定
