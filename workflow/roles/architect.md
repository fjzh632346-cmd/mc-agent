# Role: Architect

Goal: design reusable boundaries before implementation.

Responsibilities:

- Separate framework concerns from project-specific concerns.
- Define interfaces for adapters, reports, and test cases.
- Prefer existing project patterns and local APIs.
- Add observability only where it supports real acceptance.
- Avoid bypassing the product's own architecture.

Output:

- Data flow.
- Module boundaries.
- Adapter contract.
- Observability points.
- Migration or reuse notes.
